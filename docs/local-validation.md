# 本地验证记录

日期：2026-09-10。执行位置为 Windows 工作区，Python 3.12；没有连接远程服务器，没有调用真实 SGLang GPU 前向。本文记录代码验证，不记录性能结果。

## 已执行

1. 从固定上游提交的完整源码压缩包建立工作副本，导出包含 6 个文件改动的 `patches/scheduler.patch`。
2. 在临时目录恢复原始文件，执行 `git apply --check` 和 `git apply`；应用后 6 个文件与实现工作副本内容一致，Python 编译通过。
3. 执行 `python -m unittest discover -s tests -v`，11 项检查通过。
4. 对 `experiments/`、`tests/` 以及补丁涉及的 Python 文件执行编译检查。
5. 检查五个命令行入口的参数帮助，在临时合成数据上执行轨迹生成、比较表和两张分析图输出；未把这些图当作实验成果保存。

11 项检查覆盖：

- 直接提取实际上游 `SchedulePolicy` 类执行分支检查：新策略绕过全队列预匹配、禁用缓存后仍可排序、原生 LPM／HRRN 长队列回退仍保留。
- 输入长度与剩余 token 排序差异；候选来自最早入队请求，队尾保持原相对顺序。
- 全局超阈值集合不被 K 截断，阈值边界包含等号，超阈值请求不再做评分匹配。
- 完全缓存时末 token 上限、回退请求已有输出长度的处理。
- 非常数 TPS 的成本项可以改变顺序；没有成本文件时不能启用 `aged-cost`。
- 重新入队更新序号，但不会覆盖首次入队与首次准入记录。
- 轨迹可重复生成，并包含同输入长度、不同目标命中的请求组。
- 用本机临时 HTTP 服务发送拆分 SSE 行、空事件和中止事件，检查 TTFT 与成功状态。
- 失败与未准入请求保持可见，命中率仅使用成功集合的正确分母。
- 用临时合成数学样本检查非负拟合能恢复已知系数，并按 12／4 个组合划分训练和留出数据。

合成样本和模拟 HTTP 结果只在临时目录使用，不进入 `runs/` 或性能结论。上游分支检查抽取实际类定义并提供 CPU 替身，因此不代表完整 SGLang 导入、CLI 配置解析和 GPU 接入已经通过。
